# 本地任务开发工作台

## 启动

在项目根目录运行一次：

```bash
PYTHONPATH=. /home/ubuntu/miniconda3/envs/curobo/bin/python tools/run/workbench.py --open
```

地址为 **http://127.0.0.1:8070**。后续在网页里操作，不需要逐个打开终端。默认只监听本机；本轮只接仿真和只读查看，没有真机执行按钮。可用 `--port` 更换端口，`--python` 指定仿真环境。

同一项目只能启动一个工作台。关闭浏览器不停止作业，终端 Ctrl+C 会停止该服务启动的进程。意外退出后记录标记中断，不自动重跑；只回收 PID 与启动标识仍匹配的旧作业。

作业分队列运行：完整仿真和视频导出共用一个计算名额；随机摆位图片使用独立的一个预览名额，不等待完整仿真；三维查看/编辑最多同时打开四个服务；助手单独运行。同类图片预览仍会短暂排队，避免同时构建多个场景的内存峰值。查看窗口不用时，在“作业与进度”点击“停止”释放名额，仅关闭浏览器标签页不会退出对应服务。

点击对应作业的“日志与产物”查看持续刷新的日志。清扫会输出初始化、候选序列预检和阶段结果；“候选预检”不执行物理动作。首次 GPU 初始化或单次规划期间仍可能暂时没有新行，不能仅据此判断进程卡死。

## 推荐使用顺序

1. 选择“刷子清扫方块”或“微波炉长任务”。已有运行可点“导入”，选择示例或输入 `runs/...` 目录。
2. 两类任务都可进入“场景与物体”，生成连续六个 seed 的随机分布图。场景编辑器从当前版本的固定布局开始；分布图使用该版本的随机规则。
3. 在“运行与结果”点“运行一次”或“运行并导出视频”。正式运行走原有 cuRobo 和 MuJoCo。作业列表支持停止、查看日志；运行失败时仍尝试导出已有实际采样，数据不足会明确报导出失败。
4. 选择运行记录，查看视频、阶段和原报告。三维回放与 Skill 查看器在新标签页打开，初次加载需等待几秒。抓刷可以选择“抓取刷子”单独查看。
5. 对比两次记录的 seed、抓取倾角、场景 hash、成功判定与证据类型。已保存的阶段可以点选，将其作为助手提问上下文。

任务成功、作业退出、视频导出分别记录。清扫的双侧接触后 weld 标记为“仿真辅助”；微波炉保留报告中的混合仿真说明。不把视频可播放或进程退出码零当作任务成功。

## 修改场景和部件

进入“场景与物体”，点击“打开场景编辑器”。网页内会显示桌面、机械臂和所有物体，也可以打开独立窗口。单击场景中的物体，或从下拉框选择，会显示橙色选中边框。左键直接拖动模型可沿世界 XY 平移并保持高度；拖空白处旋转视角，滚轮缩放。箭头与圆环仍可完整调整 XYZ 和朝向。需要精确值时，在场景编辑器里展开“精确调整当前物体”。

点击“保存为新场景并用于任务”：原始场景不覆盖，工作台自动选用新版本，并关闭“随机摆位”，后续运行按这个名义布局初始化。若要在新布局附近评测扰动，再主动打开随机摆位并检查分布图。编辑草稿不推进物理；启动仿真后物体仍会按原流程落稳，因此悬空物体会下落。

“物体与功能部件”只负责 Concept 标注，物体之间的摆位关系统一在场景编辑器调整。固定簸箕同步 XML，动态物体通过显式完整位姿初始化，保存高度和倾斜角不会丢失。

微波炉、旧刷子场景支持编辑水平桌面：在编辑器下拉框选择“桌面”，直接拖动或使用平移箭头；展开“精确调整当前物体”输入中心 X/Y 和桌面顶高 Z（米）。在“桌面尺寸”设置长 X、宽 Y、厚度；改厚度保持顶高不变，桌面保持水平，物体不会随桌面移动。保存为新场景后，预览、MuJoCo 和纯视觉规划使用同一桌面，声明的 XY 摆位边界更新为新桌面边界，其余约束保留。扩大桌面不表示 IK 或任务一定成功。更新此功能后需重启旧工作台后台并重新打开场景编辑器；旧后台会明确拒绝保存桌面，避免修改被忽略。

保存成功不代表布局可达或无碰撞。请先生成分布图/检查初态，再运行；如果把物体拖到重叠或桌外，原有初态检查仍会报错。微波炉支持移动整机和碗；门、旋钮及支撑结构随炉体移动，不作为独立刚体拖拽。微波炉预览与正式任务使用相同构建初态，不提前推进机械臂落稳；清扫沿用其已有落稳流程。

点击“编辑部件”打开现有 Concept 编辑器；保存写入新作业目录。返回工作台，点该作业的“日志与产物”可刷新保存状态，然后在物体列表选择“应用刚保存的标注”，确认目标物体并生成新场景版本。原始标注和历史 run 不覆盖。

“抓取知识实验台”用于理解圆柱等基础几何的参数，不表示自动修改当前清扫 Knowledge。当前任务的有效抓取参数与夹爪关系应在 Skill 回放中核对。

## 固定测试与随机测试

在“运行与结果”选择“测试摆位”：

- **固定测试**：全部物体按保存布局初始化；动态物体仍会受物理影响。
- **随机测试**：按当前版本规则和 seed 采样。每个物体可单独选“固定”或“随机”；固定在世界系的物体不动，固定在另一个物体参考系的物体随该物体移动。

进入“场景与物体 → 摆位规则与预览”，配置物体的参考系、X/Y 半范围（米）和 yaw 半范围（度）。固定模式会忽略这些范围。规则不允许循环参考；随机扰动保留已编辑高度和倾斜角。

“载入 Codex 建议范围”使用本轮 Codex 编写的任务预设：微波炉默认整机固定、碗 ±2 cm / ±8°；清扫复用已有声明分布。该按钮加载本地预设，不进行模型联网推理。可修改后保存，或让 Codex 经同一场景规则接口写入新方案。规则保存成新场景版本，原输入不覆盖。

点击“预览 6 种随机摆位”，查看当前 seed 起的六个样本及原始初态记录。新预览会保存准确的 MuJoCo 模型和状态快照；每张图下点“三维查看 / 调整视角”，左键拖动画面旋转、右键平移、滚轮缩放，也可切换正面/俯视。在同一个三维窗口选择其他 seed 时保留用户视角，不重新随机采样。旧预览缺少快照时会提示重新生成。无效样本保留原因，不能冻结；有效样本可点“以此摆位固定测试”，另存完整采样 pose、来源 job 和 seed，并自动切回固定模式。之后也能打开三维场景继续检查和调整。

规则保存版本、采样 seed、名义/采样 pose 与检查结果在作业目录留存。清扫还记录落稳 pose；微波炉初态保留尚未推进物理的说明，实际后续状态由正式 Task 的 Runtime 记录。微波炉检查桌面支撑、几何穿透和离散门运动包络；这不是完整连续碰撞检查。可达性与任务结果仍由 cuRobo/实际仿真判定，不因 IK 失败静默剔除样本。

微波炉的 seed=123 旧入口限制已移除；历史成功只适用于已有记录，新的随机摆位尚未验收完整任务成功率。

## 开发助手

在右上角打开助手，先填写 `CODEX_HOME` 并点“应用目录并刷新”。支持绝对路径和 `~/`，目录须已存在；初始值来自工作台启动环境，未设置时为 `~/.codex`。模型、对话列表、历史与后续聊天都使用生效目录，仅为 Codex 子进程设置该变量，不改全局环境。

然后从下拉框选择当前项目的本地 Codex 对话，可按标题搜索并加载更多；也可以明确选择“新建对话”。选中已有对话后，点击“查看所选对话历史”，按时间顺序查看用户/助手文字，支持“加载更早记录”。工具只显示事件类型，工具输出和推理内容不展开；查看历史不会发送问题。

- **默认继续原对话**：消息写回原来的 thread，历史由 Codex 加载，不再只拼接最近六条网页消息。
- **创建分支后继续**：首次发送时从选定原对话创建分支；界面自动切到返回的分支 ID，后续消息继续该分支。
- **模型与思考强度**：从本机 App Server 提供的列表选择。留空沿用原对话或 Codex 默认；显式选择会作用于接入的对话，不修改全局配置。列表并不保证每个模型在当前账号都能调用，服务端拒绝会显示真实错误。

已选目录与对话 ID 保存在浏览器，按目录分别记忆，刷新后可再次接入。侧栏消息区显示本页消息，旧消息通过独立历史窗口查看；模型接收到的历史由 Codex 会话及其压缩机制决定。切换任务或运行记录会清空网页消息区、重置证据授权，但不创建新 Codex 对话。原对话仍在其他终端使用时，避免同时发送；接入前会检查服务可见的运行状态和最近一轮状态，有进行中的回复就报错，不抢占。该检查不能消除不同客户端同时启动的竞争窗口。

### 提供上下文、图片和文件

输入框上方的“本次上下文”列出任务、场景路径、运行报告/日志、所选阶段和附件，可取消勾选或移除。运行图片在授权后显示缩略图，可单独排除；不会因移除一张又自动补另一张。点击“预览上下文”查看报告路径、文本片段及实际图片输入清单。

- **图片**：用系统截图后在输入框 Ctrl+V；也可拖入或点“添加文件 / 图片”。
- **截图按钮**：由浏览器让你选择窗口、标签页或屏幕，取一帧后停止采集；不支持时可用系统截图粘贴。
- **本地路径**：在路径框粘贴文件/目录地址后点“添加”。文件保存为快照，目录仅附当前层清单，不递归上传。
- **发送后核对**：消息下方展开“本条消息实际提供的上下文”。作业目录的 `context.json` 保存提交时的实际快照，后续报告变化不改变该消息的输入。

单个附件不超过 10 MiB，每条消息最多 8 个附件。文本内嵌前 8000 字符并标记截断，助手可继续只读查看完整附件快照；图片作为图片输入提供。其他文件提供快照路径，不冒称已转换成文本或图片。附件集中保存在 `runs/workbench/attachments/`，移除待发送附件不会删除过去消息引用的快照。凭据/内部配置目录不作为普通附件来源。

明确提供附件后可以独立提问，不必先选运行记录。相关项目代码也可按问题只读检查。取消勾选只影响本条消息新增的上下文，不清除所选 Codex 对话已有历史。

提问会发送到本机登录配置的 Codex 服务；选择运行记录时，需明确勾选允许发送该记录的报告、日志片段和最多三张已有运行图片；手动添加的附件另计。日志作为证据而非指令。已授权的证据会随消息写入所选对话。

助手仍为只读诊断：可解释证据，不能自动改代码、启动仿真或操作机器人。接入时显式指定只读 sandbox、禁止工具授权；这也会覆盖原对话的相应配置，回到终端开发时须按终端需求重新设置权限。登录、网络、模型或超时问题保留作业失败与日志，不冒充诊断结论。

若出现 `remote compact task: workspace routing discovery failed`，表示该次回答的远程上下文压缩失败，不是仿真失败。网页显示错误原因、当前对话 ID 和恢复建议；原始错误在本次助手作业目录的 `assistant_error.json`，已有分支及部分回复保留，部分文字不算完整答案。可以在当前分支重试；反复出现时，在原终端检查对话能否正常继续，或明确选择“新建对话”并重新附加所需上下文（不继承旧历史）。工作台不会自动换模型或丢弃历史。仅提供任务名和场景路径不包含某次运行的失败证据；分析仿真失败请选中对应运行记录并检查发送清单。

“新任务草稿”保存自然语言目标和参考模板，可以交给助手分析开发步骤。草稿尚不生成新的 Skill/Task 实现。

## 文件与复现

作业集中于 `runs/workbench/jobs/<id>/`：`job.json` 是参数、argv、退出码和时间；`output.log` 是进程输出；仿真放在 `run/`；后处理视频放新目录。`library.json` 只登记导入记录、草稿和场景版本，原始运行事实仍由各任务报告提供。大报告按文件更新时间缓存摘要。

场景版本位于 `runs/workbench/scenes/`，保存来源及改动。历史 run 导出不会写回原目录：清扫录像器通过 `--manifest` 把清单写到新作业目录。

首轮验收包含：网页真实打开、清扫三种初态图、实际 Concept/Skill 窗口、HTTP/进程回归、一次 seed 36 正式 cuRobo 清扫（原任务判定成功，使用仿真辅助夹持）、历史微波炉视频、清扫实际视频和不含项目记录的本机问答。真实记录发送的端到端问答测试被自动审批拒绝，等待用户明确授权；本地上下文和授权检查由回归覆盖。单个样本不构成分布成功率。

## 交互查看与编辑的区别

随机样本三维窗口只读：拖动改变相机，不改变物体或历史数据。场景编辑器支持直接拖动物体：单击选中后出现边框，拖模型平移、拖空白旋转视角，保存后创建新场景版本。直接拖动微波炉时，门、旋钮和支撑结构作为整体移动。

2026-10-30 交互修正已实际验证：点碗/微波炉切换选中，直接拖动炉体并保存（世界位置从 .520/.290/.040 m 变为 .488/.261/.040 m）；随机三维视角拖动及切换 seed 17→18 保留视角；44 项相关回归通过。证据位于 runs/tmp/workbench/20261030_interaction/，未重新评测任务成功率。

## 纯视觉规划、Knowledge 与 Skill

在“运行”区域选择 **纯视觉规划**，再运行任务。该路径直接读取资产与 URDF，用 cuRobo 生成轨迹，不启动或导入 MuJoCo。运行方式与 **cuRobo 场景碰撞** 是两个独立选项：纯视觉 / MuJoCo 均可选择检查或忽略桌面与物体碰撞（默认检查）。保留机器人自身、机器人本体与另一机械臂的保护及关节限位；关闭规划碰撞不关闭 MuJoCo 物理接触。纯视觉规划不可直接用于真机执行。

左栏新增两个入口：

- **Knowledge 预览**：选择抓取/接触知识，显示候选 TCP、几何参数和物体，不要求先运行完整 Task。候选未做 IK/碰撞筛选。
- **Skill 预览**：选择单个 Skill，独立计算 cuRobo 轨迹，查看阶段、播放、目标与实际 FK TCP、误差及原始返回。携物操作可显式假定初始已夹持，假设记录在结果中。

原来的 MuJoCo 仿真模式保留。场景编辑、随机分布图片仍使用原有显示流程，不属于上述无 MuJoCo 规划路径。

纯视觉记录显示“规划通过（未执行）”，`task_success` 保持未知。附着、门和旋钮运动属于运动学预测；方块不会伪装成已被物理推动。规划失败也可查看已生成的前缀及原始场景。实际视频导出只用于 MuJoCo 记录，此模式不使用该按钮。

命令行也可独立打开：

```bash
PYTHONPATH=. python tools/viewers/view_knowledge.py --task sweep \
  --scene data/realworld/brush_cube_dustpan_0 --knowledge brush_grasp
PYTHONPATH=. python tools/viewers/view_skill.py --run <纯视觉规划运行目录>
PYTHONPATH=. python tools/viewers/view_task.py --run <纯视觉规划运行目录>
```

纯视觉开启场景碰撞时使用视觉资产导出环境几何，持物仅预测附着，尚未接入持物碰撞球；不能当作完整持物安全验收。

当前适配清扫与 task_1 微波炉，尚不是任意任务导入器。微波炉纯视觉版本以现有 DoorSkill 拉把手路径预测开关门，不等同于物理 Task1 的完整接触策略。

## 在线查看与失败前缀

完整 Task 在“运行与结果”页内在线播放；独立 Skill 在“Skill 预览”页播放。自动启动的查看器是单独作业，不会替换任务日志。任务失败后保留失败摘要和已保存前缀；初态检查失败、尚无实际采样时没有动作可以回放。微波炉摆位不合法会直接列出物体和检查原因，详细初态见该运行的 `placement.json`，完整异常见 `task_exception.txt`。

点击“运行一次”“运行并导出视频”或 Skill 的“cuRobo 规划并预览”后，网页立即打开在线窗口。窗口先显示等待状态，初态与轨迹落盘后逐段更新；查看器与计算作业独立，关闭查看器不会停止任务。

- 纯视觉：展示已生成的 cuRobo 阶段；计算下一段时可播放前面的阶段，不使用 MuJoCo。
- MuJoCo：展示同一任务 runtime 保存的实际 qpos，不重跑、不用规划轨迹冒充实际动作；流中保存冻结模型以核对关节顺序。
- 失败后：保留当前窗口和全部已保存前缀，可“回到起点”再播放，也可拖动时间轴。初始化失败且没有任何样本时会明确说明，没有画面可补造。
- “播放 / 暂停”只控制浏览；停止计算或仿真仍用作业列表里的“停止”。关闭“跟随新增记录”可专注检查已有前缀。
- MuJoCo 视频仍由“运行并导出视频”或运行记录的“导出视频”生成；不要求任务成功。三维在线查看与 MP4 导出是不同操作。

Knowledge 现有门板推门、把手拉门、旋钮旋转路径，以及原有抓取候选。窗口显示金色目标夹爪、候选点、蓝色路径、接触法向，支持全景/目标近景/夹爪侧面和部分几何参数重新生成。选择路径点时门和旋钮按该点的预测角度显示；所有候选仍标明未筛 IK/碰撞。参数写入本次查看器目录的 `knowledge.json`，不会自动覆盖正式 Knowledge 配置。

Skill 窗口显示目标夹爪、实际 FK TCP、蓝色规划轨迹、阶段进度和速度，可切换视角。当前覆盖常用检查交互，不是旧调参器全部功能的复制；网页场景摆位仍在“场景与物体”中编辑。

现有 CLI 可跟随正在生成的记录：

```bash
PYTHONPATH=. python tools/viewers/view_task.py --run <运行目录> --follow
```

流数据集中在该运行目录的 `live/` 下；历史运行不补写、不修改，原入口的只读回放仍可用。

## 五类 Benchmark

任务下拉框对应 `benchmarks/` 中的五类定义：微波炉、普通刷清扫、长刷清扫、杯子倾倒、勺子舀取。场景默认路径与版本读取定义，实际执行仍使用各自现有 policy，注册不代表完整任务已成功。

| 功能 | 微波炉 / 普通刷 | 长刷 | 杯子 / 勺子 |
|---|---|---|---|
| 实际运行、在线实际流、记录 | 支持 | 支持 | 支持 |
| 三维查看初态 | 支持 | 支持，使用正式长刷适配 | 支持 |
| 网页场景拖拽 / 分布图 | 支持 | 暂未接入 | 暂未接入 |
| 无 MuJoCo 规划 / Knowledge | 支持当前几何 | 暂未接入 | 暂未接入 |
| Skill 页面独立发起 | 当前纯视觉预览 | 仅已有记录回放 | 从初态运行到所选 Skill，包含前置阶段 |

长刷随机测试使用原有 `wide` 分布与 seed。杯子和勺子当前使用已生成的固定输入场景，网页随机摆位选项禁用。新杯/勺运行优先读取 `task_result.json` 的完整任务事实；不会把已成功抓取当作倾倒/舀取任务成功。

## 运行前确认场景

“运行与结果”页的 **本次运行场景** 会显示选用的版本、完整输入路径、固定/随机模式，以及随机 seed。可以直接切换已保存版本，点击“预览本次运行场景”在同页检查三维摆位；预览只初始化，不执行机器人动作。

- 选择默认场景或保存版本仅改变当前浏览器记住的任务输入，不修改终端命令默认值。
- 改变场景、运行方式、摆位模式或 seed，会关闭旧预览并提示重新预览。预览和运行使用同一份输入与初始化参数；长刷随机预览也包含正式落稳过程。
- 拖动但未保存的摆位会显示草稿提示；先在编辑器点击“保存为新场景并用于任务”，运行页将自动选用该版本。存在未保存草稿时不能发起任务。
- 预览不是 IK、碰撞规划或任务成功证明。两种运行方式与 cuRobo 场景碰撞选项仍独立。
