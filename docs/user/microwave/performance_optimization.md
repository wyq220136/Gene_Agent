## 保留的行为

- 开始本轮工作时服务器已有 `first_successful_batch` 策略，本次未改变其早停和排序边界，也未改回 `batch_all`。
- 不改变几何/碰撞约束、姿态精度、关节行程门槛、抓取后置条件、运动速度或夹爪命令范围。
- 不合并“接近但不相同”的状态。实际状态变化时正常重算；因此实测存在微小噪声时，筛选到执行的严格缓存可能不命中。
- 相机两帧校验保留：持久连接本身不能证明缓存中的帧是在本次动作之后曝光。
- 不共享同一个 cuRobo 引擎跨线程求解，不并行执行依赖前序实测终态的动作。

`runs/tmp/performance_20261126/` 保存 baseline、after、integration、targeted_final、final_regression、reuse_final 测试输出以及 GPU 对照脚本和 JSON。

GPU 对照采用仓库已保存的历史冻结场景，在同一实际起点附近构造 FK 正例，并保留原远距离目标作为拒绝负例；123/124/128 三批新旧成功/失败掩码相同。它验证批次形状复用和基本约束，不是用户最新完整 pick_bowl 的原始请求回放。

## 与默认物理仿真抓碗入口的差异

比较对象为 `simulation_bowl/pick.py` 的自动抓碗和 `realworld/microwave/pick_planning.py`，并非所有仿真/Viser 入口。

- 仿真沿用基座侧、45～70°、碗沿接触几何过滤；真机采用 AffordToolAct 候选，关闭这组仿真专用过滤。
- 仿真默认 profile 最多 40 个候选；真机上限为现场生成候选数量，并按当前首个成功批次策略筛选。
- 默认仿真 profile 不启用 `align_before_approach`；真机启用接近前原位对齐，因此增加对齐轨迹与其复核。
- 共享规划函数只在 `align_before_approach` 启用时接入候选抬升可行性前瞻；真机因此可能在正式闭爪前增加抬升规划。
- 真机存在相机/SDK 采集、阶段前复核、实际终态交接与重新规划；仿真直接读取模型状态。两者共享函数不代表调用次数相同。
- 真机默认 `motion_speed_scale=0.1`，先将规划时间除以 0.1；未显式指定 `tcp_speed_mps` 时平移速度按 `0.1 m/s × 0.1 = 0.01 m/s` 限制，再按 100 Hz 发点。MuJoCo 按仿真 timestep 推进，没有要求同等墙钟时间的 sleep；视频播放速度也不等于执行墙钟。

用户提供的 252.19 s 日志中候选筛选占 217.10 s，优先解释为规划搜索开销；该记录没有完整 close/lift 阶段，不能用来计算完整抓取成功的速度比。
