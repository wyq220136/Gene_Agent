# 场景与成功条件

## 何时读取与输入

新任务开始、改变操作目标或发现任务可能不合理时读取。输入为语言指令、RGB / 视频；需要 real2sim 时再提供同一采集的 RGB-D、相机参数和已有资产。先理解用户想操作什么、如何操作、最终应是什么状态，不把视频中的偶然摆位当成不可更改的要求。

若输入是已有仿真 benchmark，先走[原生接入流程](native_benchmark.md)。本页的重建、合理调整摆位和编写判据适用于自建题目；严格 benchmark 只读取并核对原配置，不重新定义初态分布或成功条件。

## 执行

1. 明确操作对象、工具、作用部位、阶段顺序、禁止事项和成功含义。重要歧义向用户确认。
2. 冻结原始采集，记录内外参、深度单位、时间与 frame。重建参考[桌面实例](reconstructed_tabletop_scene.md)及[单物体感知](../user/scenes/realworld_single_object_perception.md)。SAM3D / Articraft 是可选工具，当前桌面脚本不等于任意物体的一键导入器。
3. 区分 mesh 的 object frame、相机观测、仿真名义 pose 与落稳后实际 pose。明确 `T_A_B`、米/弧度、缩放是否已应用；不能直接把点云中心当完整 6D pose，也不能重复缩放。相机外参必须属于当前相机与机械臂 base，不能照抄右臂标定到左臂。
4. 分别检查 visual、规划碰撞和物理接触几何。可简化 collision，但不能封死容器入口、让手指无法进入抓取部位，或丢掉可动关节。
5. 根据机器人工作区合理布置物体；用户未禁止时可以调整摆位，但保留采集参考与调整依据。初态分布记录对象、坐标系、范围、分布、seed 和有效性规则。
6. 编写任务成功条件。除了终态，还要覆盖任务必需的过程：例如“关门后加热过”不能仅用最后门关闭判断。题目与判据放在相应 benchmark，操作策略放在 policy；沿用[现有组织](../../benchmarks/index.md)，不复制第二套资产。

## 交付与完成条件

- 交付多个初态样本的全景与目标近景，Agent 实际打开检查；不能用一张名义图代表整个分布。
- 提供能打开本次场景的 3D 命令，包含实际目录。已有 benchmark 可参考 `python tools/viewers/view_benchmark.py --benchmark <标识> --mode viser`；新场景须先实现或接入相应查看入口，不能假定只改标识就能用。
- 检查尺寸、坐标、支撑、初始穿透、关节可动关系和工作区。纯位置 IK 仅作初筛，仍需后续验证完整操作姿态、路径和接触。
- 成功条件应合理、明确，不能让策略通过与操作意图无关的捷径得分。声明哪些观测可供策略使用、哪些只供诊断或评测。

## 失败处理

先查[人类经验](../../human_experience.md)中的任务定义与资产问题。目标不可达、资产不能动或判据过于苛刻时，应明确反馈根本原因；不要持续在错误题目上搜索参数。调整题目须显式记录，不静默删除困难样本或放松判据。
