# 前言

本项目的目标之一是：把人类开发者的经验蒸馏给agent， 让agent能以一种结构化的方式来思考， 利用人类关于一些模块和真实物理世界的知识

我希望未来这个项目能做到几件事 
1. 快速的部署到新任务， 需要在人工辅助下，主要由codex自动完成
2. 能针对特定场景调参， 具有一定的位置泛化性（物体可以变动位置），且保持高成功率 ，可以在mujoco中先模拟，然后再sim2real

## real2sim任务定义

针对某个场景自动开发任务的时候， 可以不用局限于给定的物体摆放位置， 可以适当的移动物体摆放位置来保证可达性，如果用户没有明确指定说不能调整物体的话
设定物体初始摆放的分布范围的时候，应该把物体放在夹爪的可达范围内，能让它被抓取起来。让物体随机摆放（在合理的位置分布内），这样能模拟现实的情况，让策略更具备普遍性
你提供给我构建场景验收的时候，应该提供初始场景的截图，我看看初始物体的分布是否合理（你也需要检查一遍）


在真机调试之前，需要构建一个近似的仿真环境， 包含物体的分布
如果是真机的任务通过real2sim构建成了一个评测bench， 那可能会存在一些不合理之处


，仿真任务定义要【合理】且【明确】
仿真里未必要mujoco， 因为仿真的条件和真实不一样，我们使用仿真主要是解决（1）轨迹成功求解（2）碰撞（3）物体随机分布（4）non-prehensile操作（比如推门）， 其他的像pick-and-place这种操作可以假定抓取之后一定成功，这种动作也不涉及到仿真
合理就是指：机器人能完成，比如说仿真中的资产是能动的， 能被抓取起来的， 可以被机器人够到的
明确就是指：不会被reward hack掉，任务成功条件能导出我们期望机器人执行的动作，比如物体应该放到微波炉里，并且在门关上的情况下被拧旋钮加热一次。不要让机器人通过一些奇怪的方式来完成定义比较差的任务
而且仿真中的任务执行不能利用特权信息类别， 只能使用在真实世界中能获取到的信息


我有的时候任务成功条件定义不合理，导致做不出来，这时候你要及时反馈
 如果抓取碗中途会滑落， 而抓取动作没有明显的问题， 则有可能因为我们构建仿真资产不够好，可以考虑利用仿真特权让夹爪闭合的时候，碗粘在夹爪上固定住。 
因为我们仿真没有必要完全复制现实， 难免会有一些问题，所以可以通过一些处理来解决仿真中的困难。

# 真机

我希望未来大部分逻辑在仿真中开发完之后，可以在原来基础上少修改一些内容就能上真机， 我觉得真机的操作逻辑应该是可以包含仿真的逻辑的

把共同操作逻辑放在 Knowledge / Skill / Task，由仿真和真机分别调用。这样仿真也能验证真机将使用的决策流程

这样在真机上遇到问题， 修改了真机逻辑，就可以先让agent在仿真里试一遍看看修改的有没有问题

不过要注意， 真机和仿真有一些是不一样的， 比如某些物体的参数， 我在仿真里重建出的物体性质和真实世界不同， 就没有必要完全共用一套参数， 可能有些参数能公用，有些不鞥你

仿真和真机的感知不一样， 比如接触事件在真机就获取不到， 任务成功判断在真机也获取不到

真机接口和仿真也应该差不多

真机应该可以逐个运行测试skill/sub-task， 方便用户调试

另外，我们这个项目是要可扩展的， 因此gene_agent/realworld/pika_gripper.py  这种具体型号的东西就不要放在realworld的下面第一层了， 如果我们有很多夹爪的话， 会显得很臃肿

## ik问题

咱现在比较常见的就是ik解不出来的问题，我大概总结了几种解决的方案，分享一下：

1. 增大ik候选的范围。 比如说某个目标pose如果不行的话，可以让它旋转几度/平移几度，也许就能解出来。 这个功能已经在部分动作里实现
2. 允许解ik的误差。对于某些可以有误差的pose（比如推门）， 允许curobo解出来的结果差个几度、几厘米。 这个我最近给curobo加上了，应用到了部分推门的pose里， 具体怎么实现的可以问codex
3. 把某些问题的末端pose求解改成一个约束求解的问题，这样就能描述一个比较大的候选范围。可参考论文rekep, geomanip。 不过这个功能还没有实现过，我担心会让逻辑比较复杂，之后可以看看也许能用上，尤其是那种要求物体满足一定约束的任务


# 人类擅长的有：

1）. 视频理解，看出来任务中究竟是有什么问题（仅限于6.1 sol， astra我没怎么在一个长任务里试过）

2）. 仿真中的任务bench定义有问题，导致任务卡住：（1）物体资产碰撞文件不够好（2）任务完成的条件定义有问题（3）物体摆放范围不适合机械臂操作
这个时候Agent是不会去想任务本身定义有问题的，它只会去想怎么解决任务，就会卡住，这个问题本质还是出在人身上
举个例子， 我的资产制作出来， 夹爪是无法紧紧抓住的， 这个时候就不可能完成抓取的任务， 所以需要人工介入，定义任务的时候可以允许机器人的夹爪自动吸附物体

3）. 一些特定的物理世界的经验，  主要是ik求解， 比如某些动作可以允许ik求解有一些误差


调整参数的能力不够


# 遇到问题的时候， 你需要检查

1. 是否是任务定义有问题（一般在real2sim的场景中出现）
- 物体摆放位置不好（够不到）
- 任务成功定义的有问题， 或者过于苛刻
- 任务资产构建的不行（导致抓不起来、运动不正常等）
- 额外加了一些作弊的设定（比如抓取后，夹爪自动粘附;关闭重力），导致有预期之外的行为
2. 是否是pose解不出来
- 对于不那么严格的pose, 可以考虑容忍一些ik误差
- 增加ik候选范围
- 修改筛选动作的规则
- 是否是当前场景的避免碰撞的规则没有设置对， 或者应该走直线/曲线
- Hint: 你需要确定： 是哪个sub-task/ skill / pose有问题， 当时的图片是什么样的，碰撞规则是什么， 碰到了什么而失败；对于两个skill之间的过渡， 也许你需要设置一个合理的keypose
3. 是否是在操作任务上出了问题
- 抓取位置错误 / 不合理
- 运动轨迹不合理
